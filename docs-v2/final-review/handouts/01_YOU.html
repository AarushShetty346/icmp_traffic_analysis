Presenter 1 — You: sender and detective (0:00–5:00)

Your question: How can a message hide in ping timing, and what evidence can we inspect? You own The idea, Runs, Signal, and Detective. Harsh owns the decision rules, so stop at the question “Is this suspicious enough to alarm?”

Start screen: Guided case — The idea. End screen: Guided case — Guardian. Leave the mouse with Harsh.

Your five-minute route

0:00–0:45 — Give the audience a reason to care

Point at the concept diagram. Say:

“This project studies a hidden communication method. A ping is a simple network check. Its requests normally arrive about one second apart. A sender can keep the packets looking ordinary but change the waiting time between them. A short wait can stand for zero; a long wait can stand for one. We ask whether someone watching the receiver can spot that pattern.”

Do not say the site is sending packets live. This first graphic is a concept diagram.

0:45–1:30 — Make the bits concrete

Scroll to “Turn a note into packet timing.” Leave HI in Your short note, or type it again. Point at 16 bits and the blue/orange squares.

“Computers store text as bits, meaning zeros and ones. HI is two bytes, or sixteen bits. In this simple example, zero waits 0.75 seconds and one waits 1.25 seconds. The later investigation uses a subtler pair, 0.95 and 1.05 seconds, because a real question is whether the difference stays visible once the network adds delay.”

One fact to remember: one byte = eight bits. A millisecond (ms) is one-thousandth of a second.

1:30–2:15 — Show what data the project has

Click Runs in the top navigation. Point to the source banner, the 610 loaded recordings, the 0 real captures, the CSV import area, and one row in the table. Do not import a file during the timed demo.

“This is the recording table. It includes ordinary and message-carrying examples under different conditions. We can import receiver capture CSVs here and inspect their origin. Today’s included 610 runs are simulated and there are no included real receiver captures. That source label matters whenever we quote a result.”

If someone asks why 610: these are prepared examples across channels, conditions, seeds, and roles; the count is not 610 independent real experiments.

2:15–3:00 — Show the original analysis workbench

Click Signal. Point at Choose runs, the four measurement tiles, and the Inter-packet delay over time graph. Scroll a little to reveal Gap distribution if the projector allows it.

“The detector works with arrival times at the receiver. We subtract consecutive arrival times to get each gap. The Signal view compares two recordings, measures their average and variation, and shows the gap distribution. Blue is ordinary traffic; orange is the message example. This is the detailed workbench behind the simpler detective scene.”

Do not explain KS distance unless asked. It measures how different two distributions are; 0 is similar, 1 is far apart.

3:00–4:45 — Be the detective

Click Guided case, then chapter 02 Detective. Keep the defaults: Variation of 50 ms, 0.95/1.05 s · subtle, Case file A. Point at the blue reference and orange case, then the three measurements under the graph. Click A hidden message to reveal the labelled answer.

“Here is the same idea as a small investigation. The blue trace is an ordinary reference and the orange trace is the unknown case. Each point is a pause measured in milliseconds. The case’s pauses vary more, but one squiggly line is only a clue. The measurements below make the comparison repeatable. I guess this one carries a hidden message; the label confirms it because this run was generated by the simulator.”

If time allows, select Case file B and guess Ordinary pings, then return to Case file A before the handoff. Skip this if the clock is past 4:20.

4:45–5:00 — Hand off cleanly

Click Continue: Guardian. Say:

“We have a clue in the pauses. Harsh will now turn that clue into an alarm rule, count its mistakes, and test whether a defence can interfere with the message.”

Stop speaking and hand him the laptop.

Your three memory anchors

  1. Packet contents can look normal while timing carries bits.
  2. The receiver measures gaps; network variation makes them noisy.
  3. The included data is simulated, so a graph is evidence about the model.

If you get a question

  • “What is ICMP?” The protocol used by ping. We look at the arrival times of its Echo Requests.
  • “Why measure at the receiver?” The network can alter delays. The receiver sees what actually arrived.
  • “Is orange proof of an attack?” No. In this controlled run we know its label; a real case needs repeated measurements and a detector with false alarms checked.
  • “What if a packet is lost?” The analysis uses ICMP sequence numbers to avoid treating a missing request as one ordinary gap. Harsh and Aarush will discuss detection and recovery effects.

If the clock is running out: omit the Gap distribution scroll and Case file B. Preserve the final detective guess and the handoff. The Runs and Signal tabs should still be briefly visible.

Timing is a blind spot for content inspection

Firewalls and intrusion detection mostly read headers and payloads. A timing channel leaves every byte untouched and carries its message in when packets are sent. Normal traffic also varies, so a detector has to tell deliberate structure apart from ordinary noise.

Can a simple detector built from a measured normal baseline tell covert ICMP timing apart from normal ping, and how does that change once jitter and load appear?

One letter, eight gaps

The sender keeps every packet identical and only changes when it sends. A short gap means 0, a long gap means 1. Here is the letter V leaving the sender.

~0.25 sSpread of the gaps, against a few milliseconds for real ping. This is what gives it away.

From capture to verdict

  1. Capturetshark on the receiver records Echo Requests
  2. FilterKeep one flow by source, destination and ICMP id
  3. DelaysΔt = t(i) - t(i-1), skipping gaps across lost packets
  4. WindowSplit into 8, 16 or 32 request windows
  5. FeaturesMean, std, CV, IQR, entropy per window
  6. DecideFixed tolerance or p95 of normal windows
  7. ScoreDetection rate, false positives, bits decoded

Conclusions

A crude timing channel is easy to catch. Keeping false alarms down is the hard part.

What we learned

  • The spread of inter-packet delays separates the planned channel from normal ping with a wide margin.
  • Averages are useless here: the channel's mean gap stays at 1 s.
  • A baseline only holds under the conditions it was measured in. Rebuild it when the network changes.
  • Sequence numbers stop a lost packet from looking like a deliberate long gap.

Limits and next steps

  • Results on this page are simulated until the lab captures replace them.
  • A channel with small gap differences hides inside heavy jitter. Entropy features from the literature are the next thing to try.
  • A sender that copies the timing distribution of normal traffic would defeat a spread-based detector.
  • Only Echo Requests in one direction are analysed; packet fields and payloads are checked separately.

Run it on your own captures

# export Echo Request timestamps from a capture
tshark -r normal1.pcap -Y "icmp.type == 8" -T fields \
  -e frame.time_epoch -e ip.src -e ip.dst \
  -e icmp.ident -e icmp.seq -E header=y -E separator=, > normal1.csv

# baseline from normal runs, then judge and score test runs
python -m icmp_detector baseline normal*.csv --window 32 --out baseline.json
python -m icmp_detector detect test.csv --baseline baseline.json
python -m icmp_detector evaluate --baseline baseline.json \
  --normal test_normal*.csv --channel test_channel*.csv --bits 0101...

# reproduce the simulated study and this page
python -m icmp_detector study --out results
python scripts/build_site.py
